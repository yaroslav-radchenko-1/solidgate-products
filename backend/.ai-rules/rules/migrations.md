# Migrations

`synchronize` is always off. All schema changes go through TypeORM migrations — in every environment. Migrations run automatically on startup via `migrationsRun: true`.

---

## Generating a Migration

After changing an entity, run:

```bash
npm run migration:generate -- src/migrations/describe_what_changed
```

This compares the current entities against the database and generates a migration file with the necessary SQL.

Example output: `src/migrations/1234567890-describe_what_changed.ts`

---

## Migration File Structure

```typescript
import { MigrationInterface, QueryRunner } from 'typeorm';

export class DescribeWhatChanged1234567890 implements MigrationInterface {
  public name = 'DescribeWhatChanged1234567890';

  public async up(queryRunner: QueryRunner): Promise<void> {
    await queryRunner.query(
      `CREATE TABLE "order" ("id" integer PRIMARY KEY AUTOINCREMENT NOT NULL, "product" varchar NOT NULL)`,
    );
  }

  public async down(queryRunner: QueryRunner): Promise<void> {
    await queryRunner.query(`DROP TABLE "order"`);
  }
}
```

---

## Naming

- File: `<timestamp>-<snake_case_description>.ts`
- Class: `<PascalCaseDescription><Timestamp>`
- Both are auto-generated by `migration:generate`

---

## CLI Data Source

`src/data-source.ts` is a standalone TypeORM `DataSource` used only by the CLI (`migration:generate`, `migration:run`). It is **not** used at runtime — the app uses `TypeOrmModule.forRootAsync()` in `app.module.ts`.

---

## Key Rules

- Never set `synchronize: true` in production or in `app.module.ts`
- Always generate migrations after entity changes — do not write them by hand unless necessary
- Migrations are applied automatically on app startup — no need to run them manually
- Review generated SQL before committing
